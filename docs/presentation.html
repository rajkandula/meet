Meet

Video meetings in the browser: rooms, invite links, direct calls, recording and end-to-end encrypted rooms, on services you choose.

Next.js 14 MongoDB WebRTC WebSocket signaling S3-compatible storage

The problem

Running your own video meetings means solving four hard problems at once.

Signaling

Browsers must find each other and swap offers before any media can flow.

Network paths

Without a TURN relay, calls fail on many home and mobile networks.

Group size

In a mesh, every person uploads a copy of their video to everyone else.

Privacy

A media server can read every frame unless the browsers encrypt them.

And a guest with an invite link should get in without creating an account.

The solution

Two Node processes, a database and a bucket.

  • Rooms at /room/[id]: camera, mic, screen share, chat, grid and spotlight
  • Invite links that work for signed-out guests
  • Dashboard: schedule, ring a contact, live badges on recent rooms
  • Optional SFU with three simulcast layers for bigger calls
  • Encrypted rooms: the key lives in the link's #k= fragment
  • Recording in the browser, uploaded straight to your bucket

How it works

Media never passes through the app server.

The app signs a room token. The signaling server checks it and introduces the browsers. WebRTC carries the media.

The tech stack

A small, plain stack with few moving parts.

Next.js 14

App Router, React 18 and TypeScript for pages and the JSON API.

MongoDB

Official driver, no ORM. Seven collections, typed in types/.

Node + ws

The signaling server: one file, one dependency, rooms in memory.

WebRTC

Mesh by default. An SFU through /api/sfu when configured.

Web Crypto

AES-GCM frame encryption through insertable streams.

S3-compatible

Presigned PUT straight from the browser.

bcrypt

Password hashes and server-side sessions with a 30-day TTL.

JSON logs

One line per event, with secrets redacted.

Status and next steps

Released as open source on 2026-10-13. The open gaps are mostly hardening.

Works today

  • Accounts, sessions and "keep me signed in"
  • Meetings, direct calls, contacts, notifications
  • Private workspaces per user
  • Mesh and SFU calls, with simulcast
  • Encrypted rooms and browser recording
  • Installable as a web app

Not built yet

  • Password reset and rate limiting on sign-in
  • Automated tests
  • Host controls: mute, remove, waiting room
  • More than one signaling instance
  • Database indexes beyond username and sessions
  • Deleting recordings
